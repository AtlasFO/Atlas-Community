How thinking levels and overrides work

A reasoning model pays for its thinking out of the same budget as its reply. Set a level too high and a role can spend a turn's whole budget thinking and return no tool call; set it too low and it answers a question it has not considered. A model's name does not predict the workable value, so Atlas asks rather than guesses.

Providers differ in whether they take the option at all. One that refuses it says so on the first call, and Atlas drops it for that model and sends the request again, so an unsupported level costs one extra round-trip and never fails a call. Where an endpoint requires a reasoning model to stop reasoning while Atlas's tools are on the request, that requirement wins for the analyst, and the note above the table says so.

Reason and DAIR backend overrides in the environment (REASON_BACKEND, DAIR_BACKEND and their _URL, _API_KEY and _MODEL variables) are read once at server start and need a restart. Role assignments here take effect on the next call.

Every model request made for a case: analyst, director, reasoning, report, reviewer, chat, brief autofill and learner. Requests outside a case, such as connection tests and capability probes, are not recorded. A request whose reply carried no usage block is counted but not priced.

Turning a plugin on or off writes ATLAS_PLUGINS_DISABLED to .env. Plugins register once, when a run's process starts, so the change applies to the next run, not to one under way.

      

        How to write a plugin
        

          
A plugin is a Python package under plugins/<name>/, the one supported way to extend Atlas without touching core. The full guide is docs/addons.md. The minimum shape:

          
plugins/my_addon/
  __init__.py   # from plugins.my_addon.plugin import register
  plugin.py     # the Addon subclass below
  addon.yaml    # optional: name, version, description, author

          
from core.addons import Addon, tool, hook

class MyAddon(Addon):
    name = "my_addon"

    @tool()
    def hello(self, name: str) -> dict:
        """Docstring becomes the tool's description."""
        return {"greeting": f"Hello {name}"}

    @hook()
    def after_every_call(self, tool_name, args, result) -> None:
        """Runs after every tool call, fail-open."""
        ...

def register(mcp) -> None:
    MyAddon().register(mcp)

          
    
            
  1. @tool() exposes a new forensic tool, callable as my_addon.hello.
    2. 
            
  2. @hook(event="after_tool_call") observes every tool call. Its return value is ignored and its exceptions are caught, so a hook can never break an investigation.
    3. 
            
  3. A plugin must fail open: if it wraps an external program that might be missing, it checks for it and returns {"success": false, "error": "..."} instead of raising.
    4. 
          

          
From the command line, atlas addon create my_addon scaffolds this, and atlas addon list shows what is discovered. If a customer might reasonably want to turn something off, it is a plugin; otherwise it belongs in core.
